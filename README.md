# Homework：冷链运输异常归因与处置助手 MVP

## 一、题目背景

某冷链物流公司负责运输高价值、强监管商品，例如：

- 疫苗
- 生物制剂
- 高价值生鲜样本

运输过程中会持续上报以下数据：

- 温度
- 湿度
- GPS 位置
- 车门开关状态
- 电量
- 时间戳
- 运输节点事件（装车、发车、中转、签收等）

运营人员当前面临的问题：

- 出现异常后，只能人工翻日志和传感器数据
- 无法快速判断是设备故障、运输异常还是操作失误
- 无法快速给出处置建议
- 不同异常类型缺乏统一的分析口径

现在希望做一个 **“冷链运输异常归因与处置助手” MVP**，用于帮助运营人员快速判断某一运输单是否存在风险，并给出解释和建议。

---


## 二、硬性限制

### 1. 禁止使用 Java
不允许使用 Java / Spring Boot / Spring Cloud / Java 全家桶作为主实现。

### 2. 可选技术
你可以自由选择更适合的技术，例如：

- Python
- Go
- TypeScript / Node.js

### 3. 禁止套旧题模板
不允许把它做成一个“换皮知识库问答”或“简单聊天机器人”。

重点不是做聊天界面，而是做一个 **有判断逻辑、有证据链、有 AI 辅助分析能力的业务工具**。

---

## 四、任务目标

请在有限时间内完成一个 **可运行的 MVP**，帮助运营人员：

1. 查询某一运输单的完整状态
2. 发现运输过程中的异常
3. 给出异常归因判断
4. 输出建议的处置动作
5. 告诉用户“为什么这么判断”

---

## 五、必须实现的能力

### 1. 运输单查询
输入一个运输单号后，系统至少返回：

- 基础信息
- 当前运输状态
- 时间线
- 关键传感器摘要
- 是否存在风险

### 2. 异常检测
系统至少要能识别以下 4 类异常中的 3 类：

- 温度长时间超标
- 车门异常开启
- GPS 轨迹明显偏离
- 设备掉线 / 数据长时间缺失
- 电量异常下降

要求给出异常判断逻辑，而不是只说“模型判断异常”。

### 3. 异常归因
对于识别出的异常，系统要能给出 **初步归因**，例如：

- 制冷设备故障
- 中途开门操作不规范
- 运输路线异常
- 设备传感器异常
- 网络上报中断

归因不要求 100% 正确，但必须有 **依据**。

### 4. AI 辅助解释
AI 需要参与输出：

- 异常总结
- 可能原因
- 建议处置动作
- 风险等级
- 证据说明

要求：

- 输出必须结构化
- 不能只有自然语言废话
- 不能只说“建议人工排查”

示例：

```json
{
  "shipment_id": "CL-2026-001",
  "risk_level": "high",
  "summary": "运输过程存在持续温度超标和中途异常开门",
  "possible_causes": [
    "制冷设备疑似失效",
    "中转环节存在不规范操作"
  ],
  "recommended_actions": [
    "立即复核当前货物状态",
    "联系司机确认设备运行情况",
    "对异常开门时间段进行责任追踪"
  ],
  "evidence": [
    "temperature > 8C for 37 minutes",
    "door_open at 14:32 outside planned stop",
    "gps deviation 12.4km from expected route"
  ]
}
```

### 5. 证据可追溯

系统必须能告诉用户：

哪些原始数据支持当前判断
哪些规则或逻辑触发了异常识别
AI 总结基于哪些结构化结果

不允许只返回一个“看起来很聪明”的结论。

### 6. 最小交互入口

至少提供一种交互方式：

HTTP API
简单 Web 页面
CLI 工具

三选一即可，但必须可运行。
